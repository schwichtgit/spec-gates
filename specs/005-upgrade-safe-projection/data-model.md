# Data Model: Upgrade-Safe Projection

All state is plain files in the consumer repository. No new runtime
dependency beyond jq, git, and a sha256 tool (`sha256sum` or `shasum`).

## Projection manifest — `.specify/gates/.projected.sha256`

| Field  | Form                                                     |
| ------ | -------------------------------------------------------- |
| header | `# spec-gates-manifest v1 version=<X.Y.Z>` (line 1)      |
| entry  | `<64 hex>  <project-relative path>` (`sha256sum` format) |

- Written by `project.sh` after a successful projection, atomically
  (temp file + `mv`). It covers every projected file, the manifest
  itself excepted.
- Never contains `hooks.local.d/`, `policy.json`, `.upgrade-holds`,
  `attestations.jsonl`, or any file outside the projection table.
- Validation: header present, `v1`, version parses; each entry has a
  64-hex hash and a path inside the projection table. Otherwise the
  manifest is **corrupt** and the projection exits 2.
- A manifest whose version is newer than the vendored extension is a
  **downgrade** and exits 2 unless `--allow-downgrade` is given.

## Known-release table — `runtime/lib/known-releases.sha256`

`<version>\t<sha256>\t<projected path>`, one row per file per release
(v0.3.0..v0.3.6, v0.3.4 included even though withdrawn). Generated by
`scripts/known-releases.sh` from git tags. It is read only when no
manifest exists, keyed by `.specify/gates/.runtime-version`.

## Projected file classification (per path, per run)

| State      | Condition                                                   | Action                    |
| ---------- | ----------------------------------------------------------- | ------------------------- |
| `absent`   | no file at target                                           | write                     |
| `upstream` | target equals new vendored copy                             | none                      |
| `pristine` | target equals manifest hash (or known-release hash)         | replace                   |
| `edited`   | none of the above, or the file was deleted after projection | conflict (exit 3)         |
| `held`     | path listed in `.upgrade-holds`                             | skip, report              |
| `resolved` | `edited` + `--take-upstream` / `--keep-local` given         | replace / skip + add hold |

`hooks.local.d/` is not classified at all.

## Upgrade holds — `.specify/gates/.upgrade-holds`

One entry per line; blank lines and `#` comments ignored.

- `<project-relative path>`: never overwritten. Doctor: **stale** (fail)
  when the file equals the vendored upstream copy; otherwise informational.
- `ci:<step-id>`: acknowledges a CI step deliberately left out (silences
  the drift failure for that step only).

## Local extension directory — `.specify/gates/hooks.local.d/`

`<hook>/<NN-name>.sh` with `<hook>` ∈ {`protect-files`, `validate-bash`,
`validate-pr`, `pre-commit`, `commit-msg`}. Owned by the project.
Contract: [contracts/hooks.md](contracts/hooks.md).

## CI step table — `ci/steps.tsv` (shipped)

`<step-id>\t<ERE signature>`: `gates`, `canary`, `pr`. Matched against
the detected pipeline file.

## Policy addition — `git.block_bulk_staging`

Boolean, default `false`. Schema-validated (unknown fields are still
rejected). Agent boundary only.

## Hook manager (detected, not stored)

| Kind         | Signal                                                      | User-owned target                        |
| ------------ | ----------------------------------------------------------- | ---------------------------------------- |
| `plain`      | hooks dir has no hook, or the gates stub                    | hooks dir (stub install)                 |
| `husky`      | `core.hooksPath` under `.husky/`                            | `.husky/pre-commit`, `.husky/commit-msg` |
| `lefthook`   | `lefthook.yml`/`.lefthook.yml` or a lefthook-generated hook | `lefthook.yml`                           |
| `pre-commit` | hook contains `File generated by pre-commit`                | `.pre-commit-config.yaml`                |
| `unknown`    | any other non-stub hook, or another `core.hooksPath`        | none: print the call-through, exit 1     |

## Install state (for `doctor --installed-only` and preflight)

| State       | Signal                                                            |
| ----------- | ----------------------------------------------------------------- |
| `installed` | `.registry` has `gates`; vendored `extension.yml` version matches |
| `dev`       | `installed` + `.specify/extensions/gates/.specify-dev/` exists    |
| `removed`   | projected runtime present, no registry entry / vendored dir       |
| `mismatch`  | registry version ≠ vendored `extension.yml` version               |
| `dormant`   | installed, `.specify/gates/` absent                               |
